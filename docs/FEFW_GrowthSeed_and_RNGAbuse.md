# 『ファイアーエムブレム 万紫千紅』ユニット成長シードと乱数調整

**対象**　Switch 2版の公開復元コード `vexcited/fefw`、2026年11月18日に確認したコミット `df863991`。以下の関数名・フィールド名は復元プロジェクト上の名称。数値例は公開式からの計算で、製品版を用いた動作試験は実施していない。対象ソフトの更新版やBuild IDと、このコミットの対応は未確認。[固定コミット][repo]

## 1．何を特定すれば次の成長を予測できるか

| レベルアップの分岐 | 成長結果を主に決める状態 | 観測結果から分かること |
|---|---|---|
| **抽選成長** `0x8C5C60` | ユニット固有の `random_seed_`、9能力の実効成長率、能力上限、目標とする上昇種類数 | 31ビットの候補ごとにレベル全体を再現し、表示された上昇量と照合できる。 |
| **蓄積成長** `0x8C5700` | ユニットの能力別蓄積値、人物データ、実効成長率、能力上限 | この分岐の内部では `random_seed_` を抽選に使わない。同じ人物・蓄積・条件なら、表示結果だけからこのシードを識別できない。蓄積の推定と次の成長予測は別途可能。 |

どちらもレベルアップ終了時に、同じ式で `random_seed_` を1回更新する。したがって、すでにシードが分かっているなら、蓄積成長のレベルを挟んでも次のシードを追跡できる。[分岐と共通の終了処理][level]・[抽選成長][random_init]・[蓄積成長][acc_init]

## 2．ユニットに保持される状態

| フィールド（実行中の `Unit` 基準） | 扱い |
|---|---|
| `+0x1C0` / `random_seed_` | 格納型は `uint32`。確認できた初期設定処理と通常のレベルアップ更新では、最上位ビットを落とす。これらの経路を通った値の範囲は `0 … 0x7FFFFFFF`。 |
| `+0x1C4` / `lottery_seed_` | 人物別の別抽選用。確認できた初期設定経路では成長シードの次のマップ乱数を使って設定される。成長シードの代入先とは別。 |
| `+0x1C8 … +0x1D2` | 蓄積成長の補助シード作成で符号付き1バイトとして読む11個の値。9能力の蓄積処理は先頭9個を使う。末尾2個も補助シードの計算に含む。 |

`Unit_AutoGrowMasteryLevel` 内に、マップ側の乱数系列から連続2回の出力を取り、各々の下位31ビットを `random_seed_`、`lottery_seed_` に書く経路がある。同じ箇所で先頭9個の蓄積値を、人物行の対応する値 `p[i]` から `(3 × p[i]) % 100` 相当で初期化する。全加入・全生成パターンが必ずここを通るかは未確認。ゲーム全体の乱数 `g_game_random` のニューゲーム用シード制約を、そのまま各ユニットの探索範囲に適用する根拠はない。[ユニット定義][unit_type]・[初期設定と蓄積値][unit_init]

**セーブとの対応。** 復元された読み込み処理はストリームの現在位置から4バイトをリトルエンディアンで読み、`Unit+0x1C0` に格納する。ここはシードを直接確認できる場合の照合点になる。`0x1C0` は実行中の構造体内の位置であり、セーブファイルの先頭に足して読む値ではない。読み込み処理はバージョンで分岐する。[セーブの読み込み][load]

**別の消費経路。** `Unit::RollPercent(n)` は同じユニットシードから一時生成器を作り、最初の出力で保存シードを更新する。`n < 1` の判定でも更新が先に起きる。`n ≥ 1` では2個目の出力で確率判定する。後述のレベルアップ中の能力別抽選は、1能力ごとにこの関数を呼ぶ方式とは異なる。どのゲーム内行動が何回ここを通るかは、個々に確認する必要がある。[ユニット固有の百分率判定][unit_roll]

### 共通の初期化・乱数生成・次回シード

以下のPythonコードは32ビット符号なし演算を明示している。`step_seed(s)` は両分岐のレベルアップ1回分に対応する。`s=0` も有効な候補である。C#では `uint`・論理右シフト・`unchecked` で同じ演算を表せる。[生成器の定義][rng]・[更新式][next_seed]

```python
MASK32 = 0xFFFFFFFF
MASK31 = 0x7FFFFFFF

def init_rng(seed):
    value = seed & MASK32
    words = []
    for i in range(4):
        value = (1812433253 * (value ^ (value >> 30)) + i) & MASK32
        words.append(value)
    return words

def next31(words):
    x, y, z, w = words
    t = (x ^ (x << 11)) & MASK32
    u = (w ^ (w >> 19) ^ t ^ (t >> 8)) & MASK32
    words[:] = [y, z, w, u]   # 内部には32ビット全体を保持
    return u & MASK31         # 使う出力だけ下位31ビット

def step_seed(seed):
    return next31(init_rng(seed))
```

例として `init_rng(123456789)` の4語は `[2139825737, 895132265, 1250641007, 932371817]`、`step_seed(123456789) = 286067900`。抽選中に一時生成器から20回引いた場合でも、次のレベルに持ち越すのはこの `286067900` になる。

## 3．どちらの分岐を再現するか・何を入力するか

`Unit_LevelUp` は `GameRoutine_9a28e0(47)` で得たキーをゲーム変数テーブルから検索する。変数が存在し値が非ゼロなら蓄積成長、それ以外（管理オブジェクトなし、変数なし、値0）なら抽選成長を呼ぶ。**47に対応する画面上の設定名は未確定**。`Unit_LevelUp` の第2引数をそのまま成長方式フラグとして扱うこともできない。[分岐条件][level]

| 計算への入力 | 取得・解釈 |
|---|---|
| `rate[i]` | レベルアップ開始時の**実効**成長率。個人の基本値、兵種補正、スキル、該当時の騎乗補正などが関わる。`100` を超えてよい。 |
| `room[i]` | その時点の能力上限までの残り。`0` 以下の能力を抽選対象から外す。上限関数は人物と現在有効な兵種の上限、兵種の上限ボーナスを参照する。 |
| `Kraw` | 上昇目標の元になる人物データの符号なし1バイト。人物行がなければ0。`GameModeData.mode_ > 2` のとき人物行 `+0x21B`、それ以外は `+0x21A`。`mode_` は前段の変数47とも `difficulty_` とも異なる。 |
| `i` | 内部処理順は `0,1,…,8`。観測では能力の**表示名ごとの増分**を保存し、内部順への変換を別に扱う。表示順のまま9桁を連結すると候補を誤って捨てる。 |

人物値が0なら兵種側の基礎値にフォールバックしてから兵種補正を加える経路がある。また、実装には条件の合う騎乗データを段階別に引き、符号付き補正値と兵種側の係数を乗算して加える処理がある。最終値は下限0。すべての能力で「個人表＋兵種表」の二項だけで足りると仮定しない。下の参照実装には計算済みの9個を渡す。[実効率の基礎項][rate_base]・[条件付き補正][rate_mods]・[能力上限][cap]・[人物目標値の選択][pick_k]・[mode_とdifficulty_の定義][mode]

**能力名の対応には資料間の差がある。** 下表は番号と名称を照合するための資料で、ゲーム画面の並び順を指定するものではない。

| 内部／保存番号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| 復元ヘッダの列挙子（接頭辞 `k` 省略） | Hp | Strength | Technique | Speed | Luck | Defense | Magic | Resistance | Build |
| 本作専用セーブエディタが付ける保存配列の名前 | HP | 力 | 魔力 | 技 | 速さ | 幸運 | 守備 | 魔防 | 魅力 |

ヘッダには『エンゲージ』の順を参考にした旨の注記がある。本作の攻略資料には「魅力」が載っている。セーブの能力補正配列は並べ替えずに読み込まれ、上昇を書き込む候補関数も内部番号を直接添字に取るため、**保存値との突き合わせには下段を第一候補**にできる。ただし能力値を取得する `GetParam` には `g_param_orders[param_order_][kind]` の変換もある。記録は日本語名と値を保持し、内部番号への対応を、値が互いに異なる人物・職の例で一度検算したい。[復元ヘッダ][kind]・[本作専用エディタの名称][editor]・[エディタの保存構造][editor_new]・[配列の復元][gain_read]・[能力値の読み出し][param_read]・[本作の能力表][roster]

## 4．抽選成長 `0x8C5C60`

**1レベルの再現順**は「9能力の候補を作る → 1セットまとめて抽選 → 必要ならセットごと引き直す → 不足分を補完 → 能力に適用 → 次のシードへ」である。

- `rate[i] > 0` かつ上限未達の能力だけを、内部番号の昇順で候補にする。元関数は9個の実効率をいったん符号付き16ビットとして扱う。以下は通常のゲーム内の数値範囲を前提とする。
- 各候補の `rate // 100` が確定上昇量。余りが正のときだけ1回引き、`next31 % 1_000_000 < 10_000 × 余り` ならさらに `+1`。比較は厳密な `<`。たとえば200％は乱数を引かず `+2`、230％は `+2` を確定し30％を抽選する。
- `K = min(Kraw, 候補数)`。上昇量が正の**能力の種類数**が `max(1,K)` 未満なら、直前のセットの上昇量を破棄し、同じ一時生成器の続きを使って引き直す。最大4セット（初回＋3回）。`+2` でも1種類と数える。
- 最終セットでまだ `K` 種類に足りなければ、未上昇の候補から `+1` する。重みは `rate × 100`。1種類ずつ非復元抽出する。`K=0` の場合も引き直し基準は1だが、4セットとも失敗したあとの補完はない。
- 最後に各能力を `+1` ずつ適用するたび上限を再確認する。上限まで残り1で230％の場合、端数抽選は行うが、実際の上昇は最大1。表示された `+1` から30％抽選の成否は特定できない。

[対象能力の選別][eligible]・[確定分と端数判定][roll]・[引き直し][retry]・[補完と適用][fallback]

### 参照実装

`room` は能力ごとの「開始時の上限までの残り」。適用中に上限・能力の並べ替えや他能力が変わらない通常ケースでは、最後の上限再確認を `min(gain,room)` にまとめられる。特殊な補正や上限の再計算が絡む場合は、元関数と同じく適用1点ごとに `GetParam` と `GetParamLimit` を読み直す。`rate` と `room` は内部順の長さ9の整数配列、`k_raw` は非負とする。

```python
def random_level(seed, rate, room, k_raw):
    eligible = [i for i in range(9) if rate[i] > 0 and room[i] > 0]
    k = min(k_raw, len(eligible))
    rng = init_rng(seed)

    for _ in range(4):
        gains = [0] * 9
        for i in eligible:
            gains[i], remainder = divmod(rate[i], 100)
            if remainder > 0 and next31(rng) % 1_000_000 < remainder * 10_000:
                gains[i] += 1
        count = sum(gains[i] > 0 for i in eligible)
        if count >= max(1, k):
            break

    for _ in range(max(0, k - count)):
        remaining = [i for i in eligible if gains[i] == 0]
        ticket = next31(rng) % sum(100 * rate[i] for i in remaining)
        for i in remaining:                    # 内部番号の順で区間を割り当てる
            weight = 100 * rate[i]
            if ticket < weight:
                gains[i] = 1
                break
            ticket -= weight

    visible = [min(gains[i], max(0, room[i])) for i in range(9)]
    return visible, step_seed(seed)
```

同じシードを再現する際、重みの共通因子100は取り除けない。`x % (100 × W)` で引いた区間と `x % W` で引いた区間が異なるからである。`random.random()` や `randrange` に置き換えても消費列が変わる。`K=0` や候補なしの場合を含め、次回の保存シードは常に `step_seed(seed)` で計算する。[補完抽選の剰余][weight]・[共通の保存更新][next_seed]

## 5．蓄積成長 `0x8C5700`

この分岐は、能力ごとの蓄積を100点単位で上昇に変換する。目標に届かないときは候補を蓄積の大きい順に補う。同点の順位を決める補助シードは、人物の1バイトとレベルアップ**前**の11個の蓄積値から作る。`random_seed_` を変えても、他の入力が同じならこの分岐の選択結果は変わらない。[補助シードの組み立て][acc_init]・[蓄積計算][acc_carry]・[並べ替え][sort]

1. `aux = uint32((person_byte << 16) + H)`。`person_byte` は人物行 `+0x30` の符号なし1バイト。`H` は11個の**符号付き**バイトを先頭から `H = 3 × H + value` と畳み込んだ値。`init_rng(aux)` を補助用に用意する。
2. 9能力を内部番号順に走査し、上限未達かつ実効率が正なら `total = 蓄積[i] + rate[i]` を計算する。`total ≥ 100` なら商を上昇量、余りを新たな蓄積値とし、商だけ残り目標を減らす。`total < 100` なら蓄積を `total` に更新し、その能力を補完候補に入れる。対象外の蓄積はそのまま。
3. 残り目標が正なら候補をシャッフルする。各位置で `j = next31(aux_rng) % 候補総数` を引き、現在位置と `j` を交換する。毎回**同じ候補総数**で割る。続けて**更新後**の蓄積値を降順に安定ソートする。同値ならシャッフル後の順序が残る。
4. 先頭から「残り目標」と「候補数」の小さい方だけ選んで、それぞれ `+1`、蓄積を0とする。ここでの目標の差し引きは確定した**上昇量の合計**。抽選成長で数えた「上昇した種類数」と区別する。
5. 次回の保存シードは、補助シードと独立に `step_seed(元のrandom_seed_)` とする。

[商・余りと残り目標][acc_carry]・[全域からの交換][shuffle]・[安定ソートの比較][sort]・[選ばれた候補への加算][acc_apply]・[対応すると読める書き込み先][callbacks]

### 参照実装

戻り値は **成長処理が指示した加算量、処理後の11蓄積値、次の保存シード**。抽選分岐と異なり、復元された蓄積分岐は走査時に上限を調べたあと、商を一度にコールバックへ渡す。能力上限をまたぐ商が出る場合、画面上の差分は適用後の能力を読み直して求める。復元コードには加算先の内部補正を −255～255 に収める書き込みもある。両コールバックの用途は呼び出し引数と書き込み先を照合した解釈である。[コールバックの本体][callbacks]・[表示値の算出][param_read]

```python
def signed_byte(value):
    return (value + 128) % 256 - 128

def accumulated_level(seed, rate, room, k_raw, previous, person_byte):
    acc = [signed_byte(value) for value in previous]  # 長さ11
    h = 0
    for value in acc:
        h = (3 * h + value) & MASK32
    aux_rng = init_rng(((person_byte & 255) << 16) + h)

    added = [0] * 9
    candidates = []
    need = k_raw
    for i in range(9):
        if room[i] <= 0 or rate[i] <= 0:
            continue
        total = acc[i] + rate[i]
        if total >= 100:
            added[i], acc[i] = divmod(total, 100)
            need -= added[i]
        else:
            acc[i] = signed_byte(total)
            candidates.append(i)

    if need > 0 and candidates:
        count = len(candidates)
        for pos in range(count):
            j = next31(aux_rng) % count
            candidates[pos], candidates[j] = candidates[j], candidates[pos]
        candidates.sort(key=lambda i: -acc[i])       # Pythonのソートは安定
        for i in candidates[:need]:
            added[i] += 1
            acc[i] = 0

    return added, acc, step_seed(seed)
```

たとえば旧蓄積が `[80,0,…]`、実効率が `[30,20,0,…]`、全能力が上限未達、`Kraw=2`、人物バイト0とする。補助シードは `80 × 3¹⁰ = 4723920`。能力0は110点から `+1・残10`、能力1は20点からいったん `+0・残20`。残り目標は1で候補は能力1だけなので、最終的に能力1も `+1・残0` になる。元のユニットシードが `123456789` なら、次の保存値は `286067900`。

## 6．表示された成長結果からシードを絞る

### 観測の取り方

同一ユニットについて、各レベルの**直前**と**直後**を対で記録する。観測1件は下記の単位とし、1能力の成否を個別の連続乱数とみなさない。

| 記録 | 理由 |
|---|---|
| ソフトの版、ユニット、セーブ地点、開始Lv→終了Lv、成長方式 | 別系列の混在を防ぐ。同じセーブからやり直した経路には共通の開始点を付ける。 |
| 職、乗り物、スキル、実効率9個、レベル直前の能力値と上限 | 職や配備を変えた場合は別条件として評価する。上限到達で抽選対象や消費数自体が変わる。 |
| `Kraw` またはその候補、必要なら蓄積値・人物バイト | シードが正しくても引き直し条件を誤れば不一致になる。値が不明なら仮説として並行に保持する。 |
| 増加量9個（各 `+0/+1/+2/…`）、レベル間の行動 | 120％以上の能力などでは増分の数値も観測情報。装備・職変更による表示差は除く。観測間に同じユニットシードを進める処理が挟まった可能性を残す。 |

### 直列の観測を照合する

1. 既知の31ビット経路から始まるなら、最初の観測**直前**のシード候補を `0 … 0x7FFFFFFF` で走査する。0も含める。セーブから実値を読めている場合は、その1候補を使った前向き照合で実装を検証できる。
2. 候補ごとに1レベルを再現し、最終表示の9要素と照合する。不一致ならこの候補を打ち切る。途中で表示されなかった抽選セットを「観測失敗」として別に入力する必要はない。
3. 一致したら **`step_seed(s)` に移ってから** 次のレベルを照合する。必要に応じ、間に確認済みの別消費や観測していないレベルの更新を入れる。複数条件を試す場合は、試した消費数・方式・能力順も候補に付ける。
4. 「最初のシード」と「観測終了時のシード」を別々に集計する。次に特定の職で何が上がるかを知りたい場合、残った現在シードにその職の入力を与え、予測が全候補で一致するかを見る。別の観測1件を候補選別に使わず残しておくと、能力順や条件の取り違えも検出しやすい。

```text
for start in 0 .. 2^31-1 (両端を含む):
    s = start
    for o in 時系列の観測:
        必要なら、前回のレベル後から今回の直前までの別消費を s に反映する
        gains, after = random_level(s, o.rate, o.room, o.k_raw)
        if gains != o.observed_gains: この start の走査を終了
        s = after
    すべて一致した場合だけ (start, s) を残す
```

上は抽選成長だけを観測した場合の擬似コード。途中に蓄積成長が入る場合も `s = step_seed(s)` は行う。蓄積分岐の表示は蓄積状態の仮説を絞るために使い、`s` 候補そのものの棄却理由にはしない。途中の別消費が不明なら、根拠のある小範囲の回数を枝分けして照合する。候補がゼロなら、能力順・実効率・上限・`Kraw`・分岐・別消費の順に記録と実装を見直す。

**同じセーブから職・乗り物を替えて比較する場合。** AとBは同じ開始シードから別々にシミュレートし、両方の観測を満たす候補だけを残す。Aの次のシードをBに渡してはいけない。条件変更そのものにシード消費があれば、その分も各経路に含める。抽選対象の増減や引き直しで消費順も変わるので、単に同じ9個の乱数に別の閾値を当てるだけでは再現できない。一方、同一セーブ・同一条件で同一結果を繰り返しても、新しい制約は増えない。

**調整への使い方。** 現在シードの候補が出たら、選択可能な職・乗り物ごとに実効率と上限を入れ替え、同一のレベル直前シードから各9能力の上昇量を予測する。候補が複数残っても、全候補が目的の能力の上昇を予測する選択肢は選べる。職を変えてそのレベルでの引き直し回数が変わっても、それだけで次回の保存シードをずらすことはできない。ただし、今回の上昇量の差は次回以降の能力上限判定に影響し得る。[次回シードの更新][next_seed]

蓄積成長だけを繰り返した記録から `random_seed_` を求めたい場合、観測を増やしてもこの値には制約が掛からない。シード自体の取得にはセーブの値など別の情報が要る。蓄積成長の予測が目的なら、代わりに11個の蓄積値・人物バイト・目標値を調べる。初期状態が分かる場合は、各レベルの職・実効率・上限の履歴を順に適用して蓄積を復元できる。同点がない場合はシャッフルの順位が結果に影響しない。[初期蓄積][unit_init]・[同点の扱い][sort]

**実装コスト。** `2^31` 候補を32ビットの配列に並べるだけで8 GiB必要になる。全候補を保持せず、先頭の観測から順に矛盾した候補を捨てる。上記Pythonは照合仕様・少数候補の試験用で、全域走査には同じ整数式をC#等に移し、候補区間を分割できる。経路が合流した後は、現在シードと必要な付帯状態が同じ候補をまとめられる。開始シードも知りたい場合は、合流前の候補を別に記録する。

### 31ビット全体を走査した例

条件は、同じユニットが毎回「全9能力50％、すべて上限未達、`Kraw=1`」、レベル間の別消費なし。模擬開始シードは `123456789`。`1` は `+1`、`0` は `+0` で、列は内部番号順。観測した各セットには2つ以上の上昇があり、全失敗後に1種類だけ強制補完された場合は一致しない。

| 観測Lv回数 | 今回の表示 | 列全体と合う開始シード数 |
|---:|---|---:|
| 0 | — | 2,147,483,648 |
| 1 | `101011100` | 4,201,229 |
| 2 | `000001001` | 8,240 |
| 3 | `001001001` | 17 |
| 4 | `001110111` | 1 |

残った値は `123456789`。さらに5回目 `100010100`、6回目 `000111001` も一致した。**4レベルはこの入力での計算例**で、必要回数は実効率・上限・補完条件によって変わる。特に上限到達や確定上昇が多い局面では、同じ回数を観測しても情報量は少ない。

次の反例も同じ条件で成立する。開始シード `1521490162` と `1752300430` は、どちらも表示が `011100111` で、どちらも次の保存シードが `524925131` になる。他の状態も同じなら、その後何レベル観測しても過去の2候補は区別できない。一方、次の成長は同じ現在シードから予測できる。

## 7．照合用テストベクトル

特記のない能力の率は0、上限には十分な余裕がある。桁は内部番号順。ソルバーを別言語へ移す際は、最終表示に加え次回シードも比較する。

| 分岐・設定 | 期待される結果 | 確認する違い |
|---|---|---|
| 抽選 `s=0`、先頭3能力が `[30,40,50]`、`Kraw=2` | 初回 `001` を破棄し、2セット目 `110` を採用。最終 `110000000`、次回 `1900725608` | 再試行で一時生成器を先頭に戻さず、前回の成功も持ち越さない。 |
| 抽選 `s=0`、先頭2能力が `[1,2]`、`Kraw=1` | 4セットとも両方失敗。9個目の出力 `107218371 % 300 = 171` で能力1を補完。最終 `010000000`、次回 `1900725608` | `% 3` に簡約すると能力0を選ぶため誤り。 |
| 抽選 `s=123456789`、先頭3能力が `[1,2,3]`、`Kraw=2` | 4セット全失敗、能力2→能力1の順に補完。最終 `011000000`、次回 `286067900` | `Kraw=0` に変えると、同じシードで最終 `000000000`。 |
| 抽選 `s=123456789`、率 `[0,100,200,230,20,0,0,0,0]`、能力3・4の上限まで残り1、`Kraw=1` | 抽選後 `[0,1,2,3,0,0,0,0,0]`、適用後 `[0,1,2,1,0,0,0,0,0]`、次回 `286067900` | 100の倍数・端数の消費と、上限による切り詰めを分ける。 |
| 蓄積 `s=123456789`、人物バイト0、旧蓄積すべて0、先頭3能力が `[20,20,20]`、`Kraw=2` | 補助シード0。3回の交換先は `[2,1,2]`。並び `[2,1,0]` の先頭2能力が上昇し `011000000`。蓄積は `[20,0,0,…]`、次回 `286067900` | 全域シャッフル、同点の安定順、選ばれた蓄積の0クリア。 |
